# RGC performance benchmarks

Compares binaries generated by RGC against equivalent C++ (`g++ -O2` / `clang -O2`).
Every program does real computation and prints its result; wall-clock time is measured (3 runs, best of 3).

## Programs

| File | Workload | Notes |
|------|----------|-------|
| `src/fib.rg` / `fib.cpp` | `fib(38)` | Recursion + integer arithmetic; measures function calls / branches |
| `src/sumloop.rg` / `sumloop.cpp` | `sum(0..1e9)` | Integer loop; the compiler folds it into a closed-form formula |
| `src/floatloop.rg` / `floatloop.cpp` | harmonic series `Σ1/i`, 5e8 terms | Floating-point loop, cannot be folded; measures raw loop throughput |
| `src/gemm.rg` / `gemm.cpp` | naive GEMM 512×512 double | Dense compute + memory access patterns; `List.get/set` without bounds checks |

## Running

```bash
# from the project root
./benchmarks/run.sh

# or specify the RGC compiler path / C++ compiler
RGC=build/rgc CXX=g++ ./benchmarks/run.sh
```

The script automatically:
1. Compiles every `.rg` (with `build/rgc`)
2. Compiles the equivalent C++ (`g++ -O2`; if `clang` exists it also compiles a `clang -O2` comparison)
3. Runs each one and times it, printing a comparison table

## Current results (LLVM 23.1.4, x86-64, 2026-10, best of 3)

| Benchmark | RGC (built-in -O2) | C++ g++ -O2 | C++ clang -O2 |
|-----------|--------------------|-------------|---------------|
| fib(38) | 62 ms | 39 ms | 62 ms |
| sumloop 1e9 | 1 ms* | 1 ms* | 1 ms* |
| floatloop 5e8 | 348 ms | 353 ms | 352 ms |
| gemm 512x512 | 19 ms | 34 ms | 20 ms |

\* The compiler recognizes `sum(0..n-1)` as an arithmetic series and folds it into a closed-form formula, eliminating the loop entirely (<1 ms).

> RGC defaults to release (LLVM O2) with no flags needed; `-O`/`-O2` request release explicitly, `-O0` disables
> optimization, and `-g` emits DWARF debug info.

## Conclusions

- RGC ships the LLVM `-O2` optimization pipeline (see the `PassBuilder` in `src/llvm_shim.cpp`),
  producing code at the same level as `clang -O2`.
- The floating-point loop and naive GEMM beat `g++ -O2`; `fib` ties with clang (g++'s gap comes from GCC's own codegen).
- Note: the fair comparison target is clang (RGC and clang share the LLVM backend).
- Validated "ineffective" optimization directions (avoid repeating them): `-march=native` (host ISA) and
  `-ffast-math` yield no measurable gain on the benchmarks above — the bottleneck is algorithm/memory-access patterns rather than the ISA; the naive
  GEMM gain comes from source-level rewrites like cache blocking, not from the compiler layer.
